SHORT DESCRIPTION

This system is a comprehensive e-commerce analytics platform designed to help 
businesses understand their customer base and predict future sales. It uses 
machine learning models—specifically K-Means clustering for customer segmentation 
and XGBoost for sales forecasting—to transform raw transaction data into 
actionable business insights. The platform enables retailers to identify customer 
value segments and anticipate sales trends with high accuracy.

================================================================================
1. ABSTRACT
================================================================================

The proposed E-Commerce Analytics Platform addresses a critical challenge in 
modern retail: understanding complex customer behavior and accurately predicting 
future sales. Using data from 99,441 Brazilian e-commerce transactions spanning 
two years (September 2016 to August 2018), this system implements a two-pronged 
approach combining unsupervised learning (K-Means clustering) and supervised 
learning (XGBoost regression).

The customer segmentation model identifies four distinct customer groups with a 
Silhouette Score of 0.4613, enabling targeted marketing strategies. The sales 
forecasting component uses XGBoost, achieving a test Mean Absolute Percentage 
Error (MAPE) of 48.53% and an R² score of 0.8194, significantly outperforming 
the baseline Prophet model (MAPE: 149.39%, R²: 0.0247).

This documentation details the system's architecture, methodology, implementation, 
and empirical results. The platform demonstrates the practical application of 
machine learning in business intelligence, offering retailers a tool to optimize 
inventory, personalize customer engagement, and improve revenue forecasting.

E-commerce retailers face three interconnected challenges that this project

4. RELATED WORKS
================================================================================

Customer segmentation in retail is well-established in academic literature. 
RFM (Recency, Frequency, Monetary) analysis has been a standard framework since 
the 1980s for identifying valuable customers. Recent research confirms that RFM 
remains "a popular and widely used business model for determining beneficial client 
segments" (Mahfuza et al., 2022). Modern approaches extend RFM by incorporating 
additional behavioral features and applying clustering algorithms.

K-Means clustering is one of the most widely used algorithms for customer 
segmentation due to its simplicity, interpretability, and computational efficiency. 
A comprehensive literature review found that "the most commonly used segmentation 
method is k-means" across diverse datasets (Alves Gomes & Meisen, 2023), and it is 
chosen in practice for its "speedy execution time and scalability" on large retail 
datasets (Feng et al., 2024). Variations such as K-Means++ improve initialization 
and convergence properties. Alternative methods include hierarchical clustering, 
DBSCAN, and Gaussian Mixture Models, each with trade-offs in interpretability and 
computational cost.

Sales forecasting methodologies range from statistical (ARIMA, exponential smoothing) to machine learning approaches. Facebook Prophet is a time-series forecasting tool developed by Meta that decomposes time-series into trend, seasonality, and holiday effects. It is designed to be "robust to missing data and shifts in the trend" and fits "non-linear trends with yearly, weekly, and daily seasonality, plus holiday effects" (Facebook Open Source, 2025), making it popular in industry applications. Machine learning approaches like XGBoost and neural networks capture non-linear patterns but typically require more training data and feature engineering.

XGBoost (Extreme Gradient Boosting) has become the dominant algorithm in predictive modeling competitions and industry applications due to its superior performance, regularization capabilities, and interpretability features (XGBoost developers, 2023; Florek & Zagdanski, 2023). The algorithm's scalability and built-in regularization have made it a favored choice for tabular data prediction tasks. Ensemble methods combining multiple forecasting approaches are increasingly popular for hedging model uncertainty.

This project contributes to applied research by demonstrating the effectiveness of 
combining these approaches in an integrated, production-ready system.

5. NEED FOR SYSTEM
================================================================================

5.1 WHAT DOES IT DO

The E-Commerce Analytics Platform performs three core functions:

(1) CUSTOMER SEGMENTATION: The system clusters 93,358 unique customers from the 
Olist dataset into four meaningful segments based on RFM features and derived 
metrics. Each segment represents customers with distinct behavioral patterns and 
business value.

(2) SALES FORECASTING: Using 714 days of historical sales data, the system 
generates daily sales predictions for the next period. Multiple models are 
evaluated, with XGBoost selected for production use based on superior accuracy.

(3) INTERACTIVE VISUALIZATION & EXPLORATION: A web-based dashboard allows users 
to explore customer segments, view detailed statistics, analyze forecast accuracy, 
and drill down into specific customer groups.

Beyond these core functions, the system maintains a backend database (Supabase) 
for data persistence, implements authentication for multi-user access, and 
provides REST APIs for programmatic access to predictions and segmentation results.

5.2 HOW DOES IT WORK

The system operates through an integrated pipeline that transforms raw data into actionable insights. The process begins with data ingestion, where the Olist Brazilian e-commerce dataset (Online-Retail.csv) is loaded and cleaned. Orders are filtered to include only delivered items, resulting in 96,478 clean transactions across 93,358 customers. This cleaning step is critical to ensure data quality and eliminate noise from incomplete or problematic transactions.

Once data is ingested, the system performs feature engineering tailored to each modeling task. For customer segmentation, the system computes seven RFM features: Recency (days since last purchase), Frequency (purchase count), Monetary (total spending), Average Order Value, Average Basket Size, Customer Lifetime Value proxy, and a composite RFM Score. These features are then normalized to ensure equal weighting in the clustering algorithm. For time-series forecasting, a different set of 14 features is engineered, including day-of-week indicators, lags from 1 to 28 days prior, and rolling statistics calculated over 7, 14, and 30-day windows.

Model training proceeds with both algorithms working independently. K-Means clustering with k=4 segments customers based on their normalized RFM features, while XGBoost regression is trained on lagged sales data and temporal features to forecast daily sales. Both models are trained offline using historical data and serialized as joblib files for efficient deployment.

At runtime, the prediction and delivery phase ensures minimal latency. New or historical data is passed through the trained models to generate predictions in milliseconds. Results are stored in the Supabase database and immediately exposed via REST API endpoints, enabling real-time access to segmentation and forecasting results.

The frontend presentation layer is where users interact with the system's intelligence. A Next.js web interface consumes the backend APIs and renders interactive dashboards, segment analysis visualizations, and forecast charts. Users can filter customers by segment, sort by various metrics, and export results in multiple formats for integration with external tools.

The entire architecture maintains modularity, allowing for model retraining, hyperparameter tuning, and feature expansion without requiring significant architectural changes. This flexibility enables continuous improvement as new insights emerge or business requirements evolve.

6. HOW THE MODELS WORK
================================================================================

6.1 K-MEANS CLUSTERING FOR CUSTOMER SEGMENTATION

K-Means is an unsupervised learning algorithm that partitions customers into k clusters by minimizing within-cluster variance. The algorithm operates iteratively, beginning with the initialization of k centroids either randomly or using K-Means++ initialization to improve convergence. Once initialized, each customer is assigned to the nearest centroid based on Euclidean distance in the feature space. The algorithm then recomputes cluster centroids as the mean of all points within each cluster, and this assignment-recomputation cycle repeats until centroids stabilize (cease to move significantly between iterations).

In this system, k=4 was selected through elbow method analysis, a technique that plots within-cluster variance against the number of clusters to identify the optimal balance between fit quality and model complexity. Each customer is represented as a 7-dimensional vector of RFM features, and the algorithm identifies four distinct groups with different customer characteristics and business implications.

Cluster 0 comprises Lost Customers (33,207 customers, 36.8%), characterized by very low recency, minimal purchase frequency, and negligible monetary value. These customers made initial purchases but never returned, representing true churn. Cluster 1 contains At-Risk Customers (44,296 customers, 49.1%), exhibiting moderate RFM metrics with a concerning trend toward inactivity. These customers purchased regularly in the past but show declining engagement. Cluster 2 groups Loyal Customers (10,483 customers, 11.6%), who demonstrate good recency, high purchase frequency, and moderate spending. Finally, Cluster 3 represents Champions (2,273 customers, 2.5%)—the most valuable segment with excellent recency, very high frequency, and substantial monetary contribution.

Model quality is measured using the Silhouette Score, which achieved 0.4613. This score indicates moderate cluster separation, meaning customers are reasonably close to their own cluster centroid while being appropriately distant from other clusters. While a higher score (closer to 1.0) would indicate tighter, more distinct clusters, this score is considered good for real-world customer data, where natural boundaries between segments are often fuzzy.

6.2 XGBOOST FOR SALES FORECASTING

XGBoost is a supervised learning algorithm that builds an ensemble of decision trees sequentially, where each new tree is optimized to correct errors made by previous trees in the ensemble. Unlike K-Means, which works with unlabeled data, XGBoost requires labeled training data where input features are paired with target values—in this case, historical daily sales figures.

The training process begins with a baseline prediction representing the mean of all training labels. The algorithm then computes residuals by calculating the difference between actual sales and predicted sales. A decision tree is fitted to predict these residuals, capturing the patterns that the previous prediction missed. The tree's predictions are added to the ensemble using a small learning rate, which moderates the contribution of each tree to prevent overfitting. This residual-fitting process repeats iteratively, typically for 100 to 1000 iterations, with each subsequent tree refining the overall prediction by addressing remaining errors.

For forecasting next-day sales, the system leverages 14 engineered features designed to capture different aspects of sales behavior. Temporal features include DayOfWeek, Month, DayOfMonth, and WeekOfYear, encoding the day-level and seasonal timing of sales. Lag features capture historical sales patterns: Sales from 1, 7, 14, and 28 days prior provide information about immediate trends, weekly patterns, monthly patterns, and year-over-year effects. Rolling statistics computed over 7-day, 14-day, and 30-day windows quantify momentum and volatility. Together, these features capture both cyclic patterns—such as weekly seasonality where weekends differ systematically from weekdays—and trend components that reflect changing sales momentum.

XGBoost excels in this forecasting context for several reasons. The algorithm naturally handles non-linear relationships better than linear models, capturing complex interactions between features. Built-in regularization through L1 and L2 penalties prevents overfitting, a common problem when fitting complex models to limited data. XGBoost also provides feature importance rankings, revealing which variables most strongly drive predictions and enabling business stakeholders to understand model behavior. Finally, the tree-based approach provides inherent robustness to outliers, as individual extreme values affect only local tree decisions rather than distorting global model parameters.

6.3 WHY NOT PROPHET?

The baseline Facebook Prophet model achieved test MAPE of 149.39% and R² of 0.0247, both indicating poor fit. Prophet is known to excel when strong seasonal effects and several seasons of historical data are present (Facebook Open Source, 2025); however, the Olist data lacks clear seasonal patterns and few holiday effects are present. Additionally, Prophet assumes additive or multiplicative decomposition, which may not capture the complex non-linear relationships in retail sales driven by promotional events or inventory changes.

XGBoost, by contrast, achieved MAPE of 48.53% and R² of 0.8194—a dramatic 
improvement. This demonstrates the importance of matching algorithm choice to 
data characteristics.

Temporal features—DayOfWeek, Month, DayOfMonth, and WeekOfYear—encode seasonal and cyclic influences on sales. 8. MEASURING ACCURACY
================================================================================

FOR CUSTOMER SEGMENTATION (K-Means):

Silhouette Score quantifies cluster quality by measuring how similar each customer is to their own cluster versus other clusters. The metric ranges from -1 to +1, with higher values indicating better-defined clusters. The formula calculates (b - a) / max(a, b), where a represents the average distance to points in the customer's own cluster (intra-cluster distance) and b represents the distance to the nearest other cluster (inter-cluster distance). The system achieved a Silhouette Score of 0.4613, indicating good cluster separation. Points are reasonably close to their own cluster centroid and appropriately distant from other clusters, though the score suggests clusters are not perfectly separated, which is expected and acceptable for real-world customer data.

Inertia, also known as Sum of Squared Errors (SSE), quantifies the total within-cluster variance by summing squared distances from each customer to their cluster centroid. Lower inertia values indicate tighter, more cohesive clusters. This metric was used to determine the optimal k through the elbow method, wherein inertia is plotted against k values, and the "elbow" point (where inertia's rate of decrease slows significantly) indicates the optimal cluster count. A balance must be struck between minimizing inertia and avoiding overfitting, which occurs when k is too large.

Davies-Bouldin Index evaluates cluster quality by examining the ratio of within-cluster to between-cluster distances. Lower values indicate better clustering—compactness and separation without excessive overlap. This metric is commonly used in clustering evaluation to assess both cluster compactness (within-cluster scatter) and separation (between-cluster distance) without relying on external labels (Hämäläinen et al., 2023; Ikotun et al., 2025). Recent systematic reviews confirm that "the highest number of articles used the Davies–Bouldin index for cluster validation" (Ikotun et al., 2025), reflecting its popularity as a standard internal validity measure. Unlike Silhouette Score, which evaluates individual points, Davies-Bouldin Index provides an aggregate cluster quality assessment.

FOR SALES FORECASTING (XGBoost):

Mean Absolute Percentage Error (MAPE) measures the average percentage deviation of predictions from actual values, calculated as (1/n) * Σ |actual - predicted| / |actual| * 100%. Unlike absolute error metrics, MAPE is scale-independent, making it interpretable to business stakeholders: a MAPE of 48.53% indicates that, on average, forecasts deviate from actual sales by approximately 48.53%. The system achieved 28.92% MAPE during cross-validation (when training on partial data to assess generalization) and 48.53% on the held-out test set. The discrepancy between cross-validation and test MAPE is normal and suggests slight differences between validation and test data distributions, though both values are within acceptable ranges for retail forecasting. For context, retail forecasting is notoriously challenging due to noise and intermittent demand patterns (Fildes, 2021), with typical MAPE values in the 40-60% range as confirmed by industry benchmarks showing average forecast errors of approximately 49% (E2open, 2023). The M5 forecasting competition using real retail data noted that many series exhibit "intermittency, i.e., sporadic demand including many zeros", making them "difficult to predict with conventional" methods (Makridakis et al., 2021). MAPE values below 30% are considered excellent performance in volatile retail categories (Demand Solutions, 2021; McKinsey & Company, 2022) but often unattainable with two years of historical data lacking strong seasonal patterns.

Root Mean Squared Error (RMSE) quantifies prediction accuracy in absolute terms using the formula sqrt(mean((actual - predicted)²)). RMSE places greater emphasis on larger errors compared to smaller errors due to squaring, making it particularly useful for applications where large prediction errors are especially costly. The system achieved an RMSE of 6,179.02 BRL, indicating that, on average, daily sales forecasts deviate by approximately ±R$ 6,179. Given the average daily sales volume of R$ 20,034.06, this represents roughly a ±30% confidence interval, which is reasonable for inventory planning and operational scheduling.

R² Score, formally the coefficient of determination, quantifies what proportion of variance in the target variable is explained by the model. Calculated as 1 - (SS_res / SS_tot), where SS_res is sum of squared residuals and SS_tot is total sum of squared deviations from the mean, R² ranges from -∞ to 1.0. A score of 1.0 indicates perfect prediction; 0.0 indicates the model performs no better than predicting the mean value for all observations. The system achieved an R² of 0.8194 on the test set, indicating that the XGBoost model explains 81.94% of the variance in daily sales, an excellent result demonstrating the model captures the major drivers of sales variation.

MAPE, RMSE, and R² serve complementary purposes in model evaluation. MAPE informs business stakeholders in percentage terms familiar to most managers. RMSE provides absolute error estimates useful for inventory planners determining safety stock levels. R² informs researchers and data scientists about model quality and explanatory power. The comparison between XGBoost and Prophet models is dramatic: Prophet achieved 149.39% MAPE and 0.0247 R², both indicating that Prophet fails to capture the underlying sales patterns in Olist data. XGBoost's 48.53% MAPE and 0.8194 R² represent a transformational improvement, validating the algorithm selection and feature engineering choices.

9. APPROACH
================================================================================

The system development followed a structured machine learning pipeline:

PHASE 1: DATA EXPLORATION & CLEANING

The initial dataset contained 99,441 raw transactions loaded from Online-Retail.csv. Data exploration revealed the temporal range, feature distributions, and data quality issues. The team identified and removed 2,963 non-delivered orders, representing approximately 3% of the original data. These records were excluded because non-delivered orders do not represent completed customer transactions and would introduce noise into customer segmentation and sales forecasting. Missing values and duplicate records were identified and handled appropriately—missing values were either filled using domain-appropriate strategies or records were removed depending on the extent of missingness. All date fields were converted to datetime format and the complete dataset was chronologically sorted to preserve temporal relationships. The final cleaned dataset comprised 96,478 valid transactions with no missing critical values, ready for feature engineering and modeling.

PHASE 2: FEATURE ENGINEERING

For customer segmentation, the engineering process began by computing RFM metrics for each customer as of a reference date, capturing their purchasing recency, frequency, and monetary value. Features were then normalized using StandardScaler, which converts each feature to have zero mean and unit variance, ensuring that all features contribute equally to K-Means distance calculations. Without normalization, features with larger numerical ranges would dominate clustering decisions. The system added derived features including Average Order Value, Average Basket Size, Customer Lifetime Value proxy, and a composite RFM Score that combines R, F, and M with domain-informed weights. Extreme outliers—such as customers with unusually high spending or purchase frequency—were removed to prevent distorting cluster centroids and reducing model interpretability. The resulting dataset contained 90,259 customers represented by 7 features each.

For sales forecasting, the feature engineering process followed a different pathway suited to time-series prediction. Raw transactions were aggregated to daily sales totals, providing a single target value per day. Lagged features were created representing sales from 1, 7, 14, and 28 days prior, enabling the model to learn from historical sales patterns. Rolling statistics were computed over 7-day, 14-day, and 30-day windows, calculating both moving averages and standard deviations to capture momentum and volatility. Temporal features encoding day of week, month, day of month, and week of year were added to allow the model to learn seasonal and cyclic patterns. The data was split into 80% training and 20% test sets while maintaining temporal order—earlier dates for training, later dates for testing—ensuring realistic model evaluation where the model predicts future sales based on past information. The final dataset encompassed 714 days of sales data, each represented by 14 features.

PHASE 3: CUSTOMER SEGMENTATION MODELING

K-Means algorithm was applied with k=4, the value determined through elbow method analysis of the relationship between k and within-cluster inertia. K-Means++ initialization was used to improve convergence speed and reduce sensitivity to initial centroid selection. The algorithm was trained on the normalized RFM feature set containing 90,259 customers. Each customer was assigned to the cluster whose centroid was closest in the 7-dimensional feature space. Model quality was evaluated using the Silhouette Score, achieving 0.4613, confirming adequate cluster separation. The trained K-Means model was serialized to joblib format (ai_models/kmeans_model_customer_categorization.joblib) for efficient loading during inference without requiring model retraining.

PHASE 4: SALES FORECASTING MODELING

Three distinct models were developed and evaluated to identify the optimal forecasting approach. The baseline Facebook Prophet model was trained first as a point of comparison, achieving test MAPE of 149.39% and R² of 0.0247—both indicating poor fit to the Olist data. This poor performance suggested that Prophet's assumption of decomposable trends and seasonality patterns does not match the actual dynamics of this e-commerce dataset. XGBoost was subsequently trained with hyperparameters optimized through cross-validation, achieving CV MAPE of 28.92%, test MAPE of 48.53%, and R² of 0.8194. These results represent a dramatic improvement, confirming XGBoost's superiority for this forecasting task. An ensemble model combining Prophet (60% weight) and XGBoost (40% weight) was also trained, achieving intermediate performance with test MAPE of 72.34% and R² of 0.7112. The ensemble provides robustness against model-specific errors but sacrifices accuracy compared to pure XGBoost. Based on these results, XGBoost was selected as the production forecasting model and serialized to joblib format (ai_models/xgboost_model_sales_forecast.joblib).

PHASE 5: BACKEND DEVELOPMENT

The Python backend was built to serve as the central hub for model inference and data management. The API implementation exposes REST endpoints allowing the frontend to request predictions and segment analysis without direct access to model files. The GET /customers endpoint returns customer segmentation results including cluster assignments and RFM metrics. The GET /forecast endpoint returns predicted daily sales for specified time periods. The GET /segments endpoint provides aggregate statistics for each customer cluster. The GET /stats endpoint delivers cached summary statistics for dashboard display. Supabase PostgreSQL was configured as the persistent data layer, storing customer records, forecast predictions, user accounts, and activity logs. Row-Level Security (RLS) policies were implemented to restrict data access based on user authentication status, ensuring that users can only query data relevant to their organization. Authentication was secured through JWT token validation, where each API request includes a JWT token issued by Supabase upon user login, and the backend validates this token before processing requests.

PHASE 6: FRONTEND DEVELOPMENT

A Next.js-based web application was developed to provide an intuitive user interface for exploring segmentation results and sales forecasts. The dashboard implementation includes multiple pages designed for different analytical tasks. The customer segmentation page displays clusters visually through pie charts, scatter plots, and summary statistics, enabling users to understand the composition and characteristics of each segment. Interactive filtering allows users to drill down into specific clusters, viewing individual customer records with their RFM metrics and cluster membership. The sales forecast page visualizes historical and predicted sales through line charts with confidence intervals, displaying model accuracy metrics including MAPE to establish user confidence in predictions. The segment comparison page enables side-by-side analysis of cluster characteristics, supporting marketing decision-making. An admin settings page allows model retraining and parameter adjustment. Authentication was implemented using NextAuth.js, providing secure login and registration flows integrated with Supabase authentication. Responsive design ensures the interface works effectively on both desktop and mobile devices, recognizing that business users may need to access insights while traveling.

PHASE 7: INTEGRATION & TESTING

Frontend and backend components were integrated to create a functional end-to-end system. API endpoints were tested to verify they correctly returned segmentation and forecasting results in the expected JSON format. Prediction accuracy was validated by comparing model outputs against held-out test data, confirming that MAPE and R² metrics matched training evaluations. Load testing was performed using sample datasets of various sizes to identify performance bottlenecks and optimize query times. The system was deployed to a local development environment enabling team members to access dashboards and explore predictions through web browsers. Comprehensive documentation was generated specifying API contracts (input parameters, response formats), database schema details, and deployment instructions, ensuring future maintainers understand system architecture. Edge cases were tested, such as empty customer segments, missing forecast data, and authentication failures, to ensure graceful error handling throughout the application.

10. IMPLEMENTATION

TECHNOLOGY STACK

The backend infrastructure is built on Python 3.8+, chosen for its extensive ecosystem of data science libraries and production-ready capabilities. The scikit-learn library provides the K-Means clustering implementation and feature scaling utilities. XGBoost handles the gradient boosting regression for sales forecasting, while Facebook Prophet serves as a baseline model for comparison. Data manipulation and aggregation tasks are performed using Pandas, which efficiently handles large datasets and provides intuitive data transformation operations. Model persistence is managed through joblib, which serializes trained models to disk files enabling rapid loading at inference time. The REST API is built using either FastAPI or Flask, creating HTTP endpoints that the frontend can call to retrieve predictions and segment data. Supabase, a PostgreSQL database with built-in authentication, serves as the data persistence layer, while SQLAlchemy acts as an object-relational mapping layer, abstracting database interactions.

The frontend uses Next.js 14, a React framework that enables server-side rendering for improved performance and SEO, combined with TypeScript for type safety throughout the codebase. TailwindCSS provides utility-first styling, enabling rapid UI development without writing raw CSS. Recharts handles interactive data visualization, converting model outputs into user-friendly charts and graphs. NextAuth.js manages authentication flows, handling user login, registration, and session management.

Infrastructure deployment leverages Supabase's cloud PostgreSQL service, eliminating database management overhead. The Next.js frontend can be deployed to Vercel, Meta's platform optimized for Next.js applications, or alternatively self-hosted on any server supporting Node.js. The Python backend runs on Ubuntu servers, Windows machines, or within Docker containers for improved portability and consistency across deployment environments.

KEY COMPONENTS

The Data Pipeline component, written in Python, orchestrates the flow from raw data to modeled insights. It loads the Online-Retail.csv dataset, applies data quality checks and filtering to remove invalid records, aggregates transactions to appropriate granularity levels (customers for segmentation, days for forecasting), and engineers both RFM features for segmentation and temporal features for forecasting. Processed data is saved in formats suitable for model training, enabling reproducibility and version control.

The K-Means Clustering Model accepts customer RFM features in normalized form and outputs a cluster assignment (0, 1, 2, or 3) along with distance metrics quantifying how strongly each customer belongs to its assigned cluster. Inference completes in under one millisecond per customer on standard modern hardware, enabling interactive queries across all 90,000+ customers. The model is persisted in the file ai_models/kmeans_model_customer_categorization.joblib.

The XGBoost Forecasting Model takes 14 temporal and lag features as input and outputs predicted daily sales in Brazilian Real (BRL). Like the clustering model, inference completes in under one millisecond per prediction, supporting real-time forecasting updates. The model file is stored as ai_models/xgboost_model_sales_forecast.joblib.

The Scaler component stores the mean and standard deviation computed during training on RFM features. At inference time, this scaler transforms new customer data to match the statistical properties of the training distribution, a critical step ensuring that clustering decisions remain consistent with the original model training. The scaler is preserved in ai_models/rfm_scaler.joblib.

The Backend API, developed in Python, loads all trained models at startup, minimizing latency for subsequent predictions. It exposes REST API endpoints that enable the frontend to request customer segmentation results, sales predictions, and segment analytics. The API manages connections to the Supabase database, enforces authentication through JWT token validation, and handles concurrent requests from multiple frontend users.

The Database Schema implemented in Supabase organizes data across multiple tables. The users table maintains user accounts and authentication credentials. The customers table stores customer records with their cluster assignments and RFM metrics. The sales_forecasts table archives historical and predicted sales by day. The activity_logs table provides audit trails of system usage and model predictions. The dashboard_stats table caches summary statistics to minimize computational overhead when loading dashboards.

The Frontend Application, built with Next.js, renders the user-facing interface consisting of pages and reusable components. It calls backend APIs in response to user interactions, manages user authentication state, and displays model outputs as interactive visualizations and tables. The frontend provides the bridge between raw model outputs and human-interpretable business insights.

CUSTOMER SEGMENTATION RESULTS

The K-Means model identified four distinct customer groups:

CLUSTER 0 - LOST CUSTOMERS (33,207 customers, 36.8%)

This segment represents customers who made initial purchases but have not returned. Characterized by very low recency (having not purchased in 600+ days), minimal frequency (1-2 purchases total), and negligible monetary value (R$ 50-300 total spent), Lost Customers have an RFM Score of 1-2 out of 100. From a business perspective, these customers represent churn—they had contact with the brand and made a purchase decision but were not sufficiently satisfied, impressed, or engaged to return. Recovery campaigns targeting this segment would likely prove economically inefficient, as the cost of reactivation would exceed expected revenue from customers with demonstrated disengagement. However, analyzing why these customers didn't return can provide valuable insights into onboarding, product quality, or customer service failures that might be addressed to improve retention of current customers.

CLUSTER 1 - AT-RISK CUSTOMERS (44,296 customers, 49.1%)

This is the largest segment, comprising customers showing early signs of churn. They demonstrate moderate recency metrics (last purchase 90-180 days ago), moderate frequency (3-8 purchases across the observation period), and moderate spending (R$ 500-2,000 total), with RFM Scores between 40-60 out of 100. These customers represent a critical business opportunity. They have been engaged customers with proven purchasing patterns, but engagement is declining. This decline may stem from dissatisfaction, limited product relevance, competitive offerings, or simply inattention. Targeted reactivation campaigns—such as email reminders with product recommendations, special discounts on products matching their purchase history, or surveys requesting feedback on their experience—can effectively re-engage these customers before they permanently churn. The declining engagement pattern makes intervention timely and potentially high-return, as these customers already understand the brand and have demonstrated purchasing capability.

CLUSTER 2 - LOYAL CUSTOMERS (10,483 customers, 11.6%)

Loyal Customers demonstrate stable, repeat purchasing behavior with good recency (purchases within the last 60 days), high frequency (15-40 purchases across the observation period), and good monetary value (R$ 2,000-5,000 total spent), achieving RFM Scores of 70-85 out of 100. These customers represent reliable revenue generators and should be treated as valuable assets. Retention strategies should emphasize loyalty programs providing rewards for continued patronage, exclusive early access to new products, special pricing on bulk purchases, and high-quality customer service prioritizing their inquiries. Personalization is key—marketing messages and product recommendations should be specifically tailored to their demonstrated preferences rather than generic offers. These customers are less price-sensitive than other segments and will appreciate genuine recognition of their loyalty through VIP treatment and exclusive benefits.

CLUSTER 3 - CHAMPIONS (2,273 customers, 2.5%)

Champions are the most valuable segment, representing the top tier of customer value. They exhibit excellent recency (purchases within the last 14 days), very high frequency (40+ purchases across the observation period), very high monetary value (R$ 5,000+ total spent), and near-perfect RFM Scores of 90-100 out of 100. These customers generate disproportionate revenue relative to their small number—a principle commonly observed in business where a small percentage of customers drive a large percentage of total revenue. Champions should receive white-glove treatment. Retention of these customers should be the highest priority, as losing even a small number would significantly impact overall profitability. Strategies should include dedicated account management (assigning a personal account manager familiar with the customer's preferences), exclusive previews of new products, customized pricing negotiations, VIP event invitations, and personalized thank-you gestures. Their lifetime value justifies significant investment in their satisfaction and engagement. Additionally, feedback from Champions should be actively solicited and systematically incorporated into product development and service improvements, as their preferences likely align with broader market demand.

SALES FORECASTING RESULTS

SALES FORECASTING RESULTS

The XGBoost model evaluated on the held-out test set achieved Mean Absolute Percentage Error (MAPE) of 48.53%, indicating that predictions deviate from actual daily sales by an average of 48.53%. Root Mean Squared Error (RMSE) reached 6,179.02 Brazilian Real, representing typical prediction deviation in absolute currency units. Most impressively, the R² Score of 0.8194 demonstrates that the model explains 81.9% of the variance in daily sales, indicating strong explanatory power and confirming that the model has successfully identified the major drivers of sales variation.

When compared against the baseline Prophet model, the performance advantage is dramatic. Prophet achieved test MAPE of 149.39%—more than three times worse than XGBoost—and R² of 0.0247, indicating that Prophet predictions were essentially no better than simply predicting the historical average sales for every day. The reason for Prophet's failure becomes evident upon examining the data characteristics. Prophet is specifically designed for datasets with strong, consistent seasonality and clearly defined holiday effects. The Olist data lacks pronounced seasonal patterns; unlike many retail datasets that show clear peaks during holiday seasons or predictable weekly patterns, Olist sales were relatively irregular. Additionally, Prophet assumes that trends decompose cleanly into additive or multiplicative components, which may not capture the complex non-linear interactions between features in this real-world e-commerce environment.

In contrast, XGBoost's tree-based ensemble approach naturally handles non-linearities and complex feature interactions without requiring explicit assumptions about data decomposition. Feature importance analysis reveals that recent sales history—particularly sales from 1, 7, and 14 days prior—are the strongest predictors, suggesting that short-term momentum is a major sales driver. Day-of-week effects proved significant, indicating systematic differences between weekday and weekend sales. Seasonal (monthly) effects exist but are weaker, confirming the observation that Olist data lacks dominant seasonality. Rolling statistics capturing momentum and volatility also contribute meaningfully to predictions.

The ensemble model combining Prophet (60% weight) and XGBoost (40% weight) achieved intermediate performance with test MAPE of 72.34% and R² of 0.7112. While the ensemble provides some robustness by hedging against model-specific errors, the averaging process dilutes XGBoost's superior performance, resulting in predictions less accurate than pure XGBoost. Consequently, pure XGBoost was selected as the production forecasting model.

13. WHY THESE RESULTS MATTER
================================================================================

   BUSINESS IMPACT OF SEGMENTATION

   The customer segmentation model generates immediate value by enabling intelligent resource allocation. Rather than treating all 93,358 customers identically with generic marketing campaigns and standardized service levels, the system identifies 2,273 Champions worthy of maximum marketing and retention investment. These customers, representing just 2.5% of the customer base, likely drive 30-40% of total revenue. Even modest improvements in Champion retention—such as a 2% increase in retention through enhanced loyalty programs—directly translate to significant bottom-line impact. Simultaneously, the system identifies 44,296 At-Risk customers representing nearly half the customer base. Systematically targeting these customers with timely reactivation campaigns—email reminders, personalized discount offers, or product recommendations based on purchase history—can proactively prevent churn before it occurs. Research in marketing indicates that RFM-based segmentation models enable more effective targeting by identifying "beneficial client segments" with distinct behavioral patterns (Mahfuza et al., 2022), allowing campaigns to be tailored to specific customer needs rather than using generic mass-marketing approaches. The system explicitly identifies 33,207 Lost Customers for exclusion from expensive reactivation attempts. While this exclusion may seem harsh, it reflects economic reality: customers who haven't purchased in 600+ days have demonstrated through their behavior that they are unlikely to respond to reactivation efforts, and attempting to win them back diverts resources from higher-probability At-Risk customers.

   Product development and inventory management also benefit from segmentation insights. By analyzing purchase patterns within each segment, the organization can identify which product categories appeal to Champions versus other groups. If Champions preferentially purchase premium products, this signals market demand for high-quality offerings. If Lost Customers were concentrated in discount-seekers, it suggests that price competition may not be viable for retention. These insights guide assortment planning, ensuring that inventory reflects customer preferences and maximizes sell-through rates.

   BUSINESS IMPACT OF FORECASTING

   Accurate sales forecasting directly impacts operational efficiency across multiple business functions. Inventory planners can stock appropriate quantities—the 48.53% MAPE means they can expect daily sales to fall within roughly ±30% of predictions given the R$ 20,034.06 average daily volume. This enables better decisions about safety stock (additional inventory held against unexpected demand spikes) and prevents both over-stocking (which ties up capital and risks obsolescence) and under-stocking (which loses sales and frustrates customers). With the baseline Prophet model's 149.39% MAPE, such informed inventory decisions would be nearly impossible; the forecast would be too unreliable for operational planning.

   Revenue forecasting becomes more accurate and enables better financial planning. Finance teams can forecast monthly and quarterly revenue with reasonable confidence, supporting budgeting for operational expenses, capital investment, and strategic initiatives. Quarterly business reviews can present data-driven sales targets rather than purely historical averages or top-down mandates, improving the realism and buy-in of forecasts throughout the organization.

   Staffing and operational scheduling benefit from demand forecasts. Customer service and order fulfillment teams can be scheduled based on predicted order volume—ramping up staff before predicted high-demand periods and reducing staff during valleys. This optimization improves labor utilization, reduces overtime costs during peaks, and maintains service quality by ensuring adequate staffing when customer volumes surge.

   Marketing campaign timing becomes optimized. Campaigns launched during predicted sales momentum periods (when the forecast suggests strong demand) are more likely to succeed, as marketing spend leverages natural demand tailwinds. Conversely, campaigns during predicted downturns are less efficient, as marketing must overcome weak baseline demand. By scheduling campaigns to align with positive forecast trends, the organization amplifies campaign ROI.

   METHODOLOGICAL CONTRIBUTION

   This project demonstrates that:
   1. Machine learning algorithms are sensitive to data characteristics; one-size-fits-all 
      approaches (Prophet for all time-series) fail
   2. Ensemble methods can provide robustness but single-algorithm selection (XGBoost) 
      provides superior performance if properly validated
   3. Feature engineering matters: Temporal features + lags capture more variance than 
      raw time-series alone
   4. Proper evaluation with multiple metrics (MAPE, RMSE, R²) is essential for 
      holistic model assessment

This project presents an integrated E-Commerce Analytics Platform combining customer 
segmentation and sales forecasting to enable data-driven retail decision-making.

KEY ACHIEVEMENTS:

1. Customer Segmentation (K-Means)
   - Successfully segmented 93,358 customers into four actionable groups
   - Silhouette Score of 0.4613 indicates good cluster quality

     44,296 At-Risk, and 33,207 Lost customer groups

   - Achieved 48.53% MAPE and 0.8194 R² score on test data
   - Outperforms industry-standard Prophet by 3x (149.39% MAPE)
   - Provides actionable daily sales predictions for inventory and revenue planning

   - Implemented complete end-to-end system: data pipeline → modeling → REST API → 
     web interface
   - Multi-user capable with authentication via Supabase
   - Real-time inference with sub-millisecond latency
   - Modular architecture enabling future improvements

4. Technical Excellence
   - Applied industry best practices: proper train-test splits, cross-validation, 
     multiple evaluation metrics
   - Normalized features appropriately for each algorithm
   - Feature engineering from domain knowledge (RFM analysis, temporal patterns)

LIMITATIONS & FUTURE WORK:

1. Data Recency: Models trained on 2016-2018 data; current (2024) e-commerce 
   patterns may differ. Periodic retraining recommended.

2. External Factors: Models do not account for promotions, competitor actions, or 
   macroeconomic factors that influence sales.

3. Segmentation Stability: K=4 is somewhat arbitrary; different values of k might 
   reveal different insights. Dynamic k-selection could improve robustness.

4. Forecast Horizon: 30-day forecasts are more reliable than 90-day; longer 
   horizons accumulate error.

5. Scalability: Current system handles Olist dataset (90K customers) efficiently; 
   multi-million customer bases would require distributed computing.

Future enhancements:
- Implement deep learning models (LSTMs, Transformers) for sequence modeling
- Add external features: macroeconomic indicators, promotional calendar, competitor data
- Develop recommendation engine: suggest products to specific customer segments
- Create automated alerting when forecasts exceed confidence intervals or churn risk spikes
- Build feedback loops to retrain models quarterly with new data

CONCLUSION:

This platform demonstrates the practical value of machine learning in e-commerce. 
By transforming raw transaction data into customer insights and sales predictions, 
it enables retailers to make informed decisions about marketing allocation, 
inventory management, and revenue planning. The system is production-ready, 
scalable, and provides a foundation for ongoing analytics and AI capabilities.
